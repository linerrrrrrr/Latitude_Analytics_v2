# 公网爬虫接口只读体检报告（2026-08-24）

> **非规范、只读诊断。** 本报告只总结 2026-08-24 的低频测试、公开来源研究和浏览器
> 核验。它没有写入 `FUTURES_LAKE_ROOT`，没有回写任何正式日历或完成状态，没有修改正式
> 代码/配置，也不构成未来生产运行授权。

## 1. 结论摘要

本次低频串行探测没有观察到 HTTP 403/429/5xx、拦截页、JSON 伪装成 HTML、重复键、
越界日期或字段缺失。最终修正版 coverage 的 28 个业务请求中 27 个为 `passed`、1 个为
`warning`、0 个为 `failed`，也没有触发主机停机；唯一业务警告是
`MYSTEEL_TIN/EMI00135906` 明确返回 `code=9201, 返回数据为空`。此前 3 轮 smoke 的
18 个逻辑请求也全部得到 HTTP 200 和稳定语义摘要。

因此当前主要风险不是“接口整体不可达”，而是“HTTP 可达但业务实体或发布时间错误”：

1. `MYSTEEL_TIN` 对无日期限制的最早、最晚边界查询也都为空，说明不是近期单日漏数；
2. 浏览器打开 `hyzs_` 与 `hyzs_list_` 两个页面入口均显示“不存在或已删除”，且菜单没有锡，强烈指向 ID 下线、改号或转发终止；
3. `XINHUA_IRON_ORE` 的实际页面只称“铁矿石指数:综合”，近期返回日频量级，与公开的周频
   “新华—中国铁矿石价格指数”身份不一致；
4. 当前外部指数日历把全部 19 个实体都按普通工作日 required，未表达各发布方日历和日内
   发布时间；
5. CPI/PPI/GDP 静态可用日可能早于国家统计局真实发布日期，SHIBOR 同日规则也没有等待
   11:00/12:00；首次空响应可能被正式记为已完成，从而不再日常补拉；
6. 生意社正式 raw 契约只证明原字节和摘要一致，不能发现 HTTP 200 的业务空页或反爬替代页。

## 2. 测试边界与证据

测试程序采用：

- 串行、并发数 1；
- 默认请求间隔 5 秒，coverage 加 0—0.5 秒抖动；
- 不做业务自动重试；
- 连接错误、403/429/5xx、无效 JSON 或拦截词触发同主机停止；
- 只保存状态、延迟、摘要、结构指标和 SHA-256，不保存整份业务响应。

本报告使用下列最新适用证据：

- [`results/coverage_20260824T023557967625+0800.json`](results/coverage_20260824T023557967625+0800.json)：
  最终修正版完整覆盖证据；含三态诊断、请求 ID 核对、内部缺口区间和未评估尾部；
- [`results/smoke_20260824T021138+0800.json`](results/smoke_20260824T021138+0800.json)：
  三类来源 3 轮性能/稳定性样本；
- [`results/coverage_20260824T021918+0800.json`](results/coverage_20260824T021918+0800.json)：
  生意社 5 个连续工作日；

  19 个行业指数近期范围；

  Tin 全系列最早/最晚边界；
- [`results/coverage_20260824T021342+0800.json`](results/coverage_20260824T021342+0800.json)：

`smoke_20260824T021115+0800.json` 与
`coverage_20260824T023537443491+0800.json` 的连接错误都是本机沙箱以
`WinError 10013` 阻止联网；相同命令获准联网后成功。两者不是远端封禁、接口性能或
反爬结论，故不计入服务可用率。

最终 robots 复核中，生意社返回可解析的 `text/plain` 且允许目标路径；Eastmoney 的
`/robots.txt` 返回 HTTP 200 JSON catch-all，无法解析成 robots 指令。本工具将后者记为
`warning/inconclusive`，既不把它当作许可，也不把它误判为远端封禁，并继续执行 5 秒
同主机限速。

## 4. 生意社页面结果

对 2026-08-17 至 2026-08-21 五个连续中国工作日的页面逐日检查：

- 5/5 HTTP 200；
- 5/5 标题日期与请求日一致；
- 5/5 存在 `table#fdata`；
- 每日均为 54 个商品行；
- 直接单元格空值、`null/none/nan` 类文本均为 0；
- 5/5 显示 `16:30` 发布时间；
- 5/5 包含“现期差=现货价格-期货价格（期货价格为结算价）”；
- 未发现拦截词或乱码替代字符；
- 首批单次延迟 0.264—0.329 秒；最终复验为 2.005—6.262 秒，正文仍约 60 KB 且结构、
  日期和语义摘要正常。

这说明样本日页面目前可用且业务结构正常，但响应耗时有明显批次波动；30 秒 read timeout
仍有充分余量，不能因首批亚秒结果而缩短超时或提高并发。正式 raw 入口只核验 HTTP 状态、
字节和摘要。
若以后收到 HTTP 200 的登录页、验证页、空页或日期错页，正式 raw 契约仍可能把它记为成功。
本诊断项目应保留为人工旁证，不应未经授权改变 raw 归档政策。

建议当天页面在北京时间 17:00 后检查；过早请求可能尚未形成 16:30 版本。

### 5.1 Tin 的判断

`EMI00135906` 的近期范围、全系列最早一条和全系列最新一条三个独立查询均返回：

```text
HTTP 200
success=false
code=9201
message=返回数据为空
```

应用内浏览器打开对应 `hyzs_` 与 `hyzs_list_` 页面时，二者均显示“不存在或已删除”，页面
菜单没有锡；相邻 Nickel/Zinc 页面正常。与此同时 Mysteel/中国价格协会公开目录仍列
“镍锡”。因此目前最合理的解释顺序是：

1. Eastmoney/Choice 指标 ID 已下线或改号；
2. Eastmoney 停止转发该指标；
3. 当前配置从一开始就使用了错误 ID；
4. “锡市场没有价格”是最低可信解释。

这不是典型封禁：同一主机、同一批次的其余 18 个 ID 正常，响应是稳定、可解释的 JSON
业务错误，而不是 HTML 验证页或统一空响应。

建议在用户授权正式修改前，先向 Choice/Mysteel 核对新 ID；正式策略应将旧 ID 设
`active_to` 或停用 required，不能填 0、前值填充或把其他锡价格静默写入原系列。

### 5.2 铁矿石身份风险

当前配置把 `EMI00064805` 命名为“新华中国铁矿石价格指数”。浏览器页面标题却只有
“铁矿石指数:综合”，近期接口返回 84 行，呈日频工作日量级；公开的真正“新华—中国铁矿石
价格指数”说明为每周二发布。

因此需要先核对 Choice 元数据：

- 如果 `EMI00064805` 不是新华指数，当前项目发布方和名称错误；
- 如果它确是新华系列，公开频率与接口近期频率冲突，需要解释版本或方法差异。

在核实前，不应把它作为“新华周频指数”解释，也不应仅根据配置名称寻找替代源。

## 7. 发布时间与“过早确认空”风险

当前项目规则：

- SHIBOR：周一至周五同日可用；
- CPI/PPI：次月 9 日，周末后移；
- PMI：一般月末，2 月使用 3 月 4 日；
- GDP：季末后第 16 天；
- 所有 19 个外部指数：普通工作日 required。

公开发布事实表明这些只是候选规则：

- SHIBOR 官方 11:00 发布，Tushare 约 12:00 更新，并有中国业务日而非单纯 weekday；
- 2026 年 CPI/PPI 有 11 日、14 日发布的月份；
- 2026Q1 GDP 在 4 月 17 日发布，比“季末+16 天”晚一天；
- Baltic dry/tanker 在伦敦 11:00—16:00 发布，北京当天白天尚未完成；
- Mysteel 日度指数通常 17:30 发布；
- 生意社页面显示 16:30。

若生产入口在这些窗口前请求并把无精确值响应记作 `empty_confirmed`，该格点会成为“已完成
的 0 行事实”，日常差集可能不再重拉。这是当前最重要的正式链路风险。

建议的只读诊断时间：

- SHIBOR：北京时间 12:10 后；
- 生意社：17:00 后；
- 国内行业指数：18:00 后；
- Baltic/WTI：北京次日上午采前一发布日；
- CPI/PPI/PMI/GDP：国家统计局年度日程所列时点后至少 1 小时，并允许供应商转发缓冲。

## 8. 反爬与错误数据判断

### 8.1 浏览器与 HTTP 交叉核验

- 生意社可见页面显示 2026-08-21、16:30、54 个商品行和现期差定义，与 HTTP 结构摘要一致；
- Eastmoney GDP 可见页面正常呈现 2026 年上半年及一季度数据，与宏观 JSON 的最新季度相容；
- `EMI00064805` 可见标题是“铁矿石指数:综合”，没有“新华”字样，且表格为工作日量级；
- `EMI00135906` 两个页面入口均显示“不存在或已删除”，与 JSON 全范围 `9201` 相互印证；
- 应用内浏览器直接导航 `datacenter-web.eastmoney.com` JSON URL 时出现
  `ERR_BLOCKED_BY_CLIENT`，但同一时段低频 HTTP 请求成功、普通 Eastmoney 页面正常渲染。
  这是浏览器客户端/隐私层阻断证据，不是源站 ban；因此反爬判断必须同时看请求证据和
  面向人的页面，不能只看浏览器导航错误。

### 8.2 本次没有观察到的信号

- 403、429、5xx；
- `Retry-After`；
- 登录/验证码/安全验证 HTML；
- JSON 接口返回 HTML；
- 页面标题日期错配；
- 字段被删除、重复键、越界日期；
- 指数值全零、全部恒定或非有限。

### 8.3 生产监控应继续区分的信号

| 信号 | 更可能的解释 | 动作 |
|---|---|---|
| 单一 ID 长期 `9201`，邻居正常 | 实体撤销/改号/覆盖终止 | 停止该实体，查元数据，不加快重试 |
| 同主机全部 ID 同时空、同一小正文摘要 | 上游故障或软封禁 | 停止主机，浏览器核验 |
| JSON 变 HTML、出现验证码/安全验证词 | 反爬页 | 立即停止，不归类为业务空 |
| 403/429 或 `Retry-After` | 明确限流/拒绝 | 遵从等待，不自动业务重试 |
| HTTP 200 但页面日期、标题或表格错 | 错误内容/缓存/软拦截 | 保存摘要证据，停止提交 |
| 延迟与正文大小突变，语义摘要同步变化 | 上游结构或网关变化 | 浏览器和历史基线双重核验 |

建议保留一个低成本 canary，而不是对全部实体高频探测；在 canary 失败后停止同主机后续调用，
可同时降低 ban 风险和错误数据写入风险。

## 10. 建议优先级

### P0：防止错误完成状态

1. 在未到发布窗口时禁止写 `empty_confirmed`；
2. 将“尚未发布”“来源实体失效”“已发布但精确值为空”“接口拒绝”分开；
3. 核实并停用/迁移 `EMI00135906`；
4. 核实 `EMI00064805` 的真实发布方和系列名称。

### P1：建立逐实体发布元数据

为每个指数保存频率、发布日历、时点、时区、延迟、有效期和修订政策；外部市场日历不要再
用同一个普通工作日规则覆盖全部 19 个系列。

### P2：低频反爬监控

- 默认串行 5 秒加抖动；
- 不自动业务重试；
- 主机级熔断；
- 保存响应摘要、结构指标和错误正文摘要；
- 浏览器核验 canary 与异常实体；
- 不把本次低频成功外推成并发许可或无上限调用能力。

### P3：官方来源迁移评估

宏观与 SHIBOR 优先评估官方源；私人指数逐项确认许可和方法。替代源必须建立新的身份和
