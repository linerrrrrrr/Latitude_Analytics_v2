## 测试前提与情景解释

| 条件或情景 | 用途与假设 |
| --- | --- |
| 契约化临时日历、事实与模拟 JQData | 检验业务结果与事务；未调用真实 API，未读写正式湖数据。 |
| 同月修复与待采日期并存 | 证明先修复的日历状态不会被稍后采集覆盖。 |
| 事实成功、日历失败后再次运行 | 对应两个独立提交边界，验证无 API 状态修复。 |
| 首次备份、安装、进入事务、正式复读及恢复失败 | 显式注入异常验证文件恢复和现场留存，不假定正式文件会自行损坏。 |
| 主键和行数相同但值不同、非法状态、错误 Schema 身份或 nullable | 检查现有验收仍能拒绝错误输出；没有因此增加新的全表防御扫描。 |
| 日志输出抛错 | 确认先恢复旧目标，再报告恢复日志。 |
| 单写入者、同一文件系统、正常 Python 异常退出 | 与共享模块边界一致；未模拟并发写入、强杀、断电或跨文件系统事务。 |

没有运行真实生产批次，因此不声称已经验证真实网络表现或正式全量运行时长。没有修改共享事务模块本体、数据 Schema、operations 编排或其他业务入口。
